# 녹음 회의록

휴대폰 녹음 파일을 올리면 화자별 대화록과 회의록(회의 주제, 논의 과정, 결론, Task)을 만들어 주는 웹페이지입니다.
서버 없이 브라우저에서 사용자 본인의 Gemini API 키로 Google에 직접 요청합니다.

**사용하기: https://gyugyu98.github.io/meeting-minutes/** (Gemini API 키만 있으면 됩니다)

## 내 PC에서 실행

`index.html`을 더블클릭해 브라우저(Chrome, Edge)로 엽니다. 서버는 필요 없습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 화면 5단계 (시작하기, 녹음 올리기, 처리 중, 화자 이름, 회의록) |
| `style.css` | 화면 스타일 (라이트/다크) |
| `gemini.js` | Gemini API 호출: 모델 선택, 파일 업로드, 받아쓰기 전용 모델 호출, JSON 생성 요청, 재시도 |
| `app.js` | 화면 동작: 녹음 자르기, 받아쓰기, 회의록 정리, 화자 이름 바꾸기, 양식 관리, 복사 |
| `templates.js` | 회의록 양식: 저장, 파일에서 읽기(md·txt·docx·hwp·hwpx), 마크다운 ↔ 화면 변환, 양식 파일(hwpx·docx)에 채우기 |
| `vendor/` | 필요할 때만 불러오는 라이브러리: JSZip 3.10.1(hwpx·docx 읽고 쓰기), hwp-convert 1.12.0을 일반 스크립트로 다시 묶은 파일(hwp 글자 구성 읽기, 기본 서식 hwpx 만들기) |
| `CHANGELOG.md` | 변경 이력 |

## 처리 방식

| 단계 | 모델 | 요청 수 |
|---|---|---|
| 받아쓰기 | `gemini-3.5-transcribe` (받아쓰기 전용, 화자 구분 내장) | 30분마다 1번 |
| 회의록 정리 | Flash-Lite (`gemini-3.5-flash-lite` 등) → 하루 한도에 걸리면 Flash | 회의당 1번 |

- 받아쓰기 전용 모델은 화자 구분을 켜면 요청 하나에 30분까지 받습니다. 30분 이하 녹음은 원본 파일을 그대로 올리고, 더 길면 브라우저에서 녹음을 풀어(16kHz) 29분 이하 조각의 wav로 잘라 올립니다(조각 2개씩 동시에).
- 받아쓰기 요청은 `audioTranscriptionConfig: { languageCodes: ['ko-KR'], diarization: true }`입니다. 단어별 시각(`wordTimestamp`)은 정확도를 떨어뜨린다고 문서에 나와 있어 켜지 않습니다. 응답에 시각이 없으면 글자 수 비율로 어림잡아 `≈`를 붙여 보여줍니다.
- 조각마다 화자 번호가 따로 매겨지므로, 회의록 정리 요청에서 대화 흐름을 보고 회의 전체 번호로 맞추게 합니다(`speakerMap`). 짝을 못 찾은 화자는 새 번호를 받고, 화자 이름 단계에서 같은 이름을 넣어 합칠 수 있습니다.
- 받아쓰기 전용 모델을 쓸 수 없으면(키에 열리지 않음, 하루 한도) Flash-Lite에게 지시문으로 받아쓰게 합니다.
- 받아쓰기가 끝나면 올린 녹음 파일을 Google에서 바로 지웁니다.
- 회의록 정리는 추론을 낮게 설정하고 스트리밍으로 받습니다. 정리 수준을 바꿔 다시 정리할 때는 대화록 텍스트만 보내므로 요청 1번만 씁니다.
- 분당 한도에 걸리면 Google이 응답에 알려준 시간만큼 기다렸다 다시 시도합니다. 하루 한도에 걸리면 멈추고, 창을 닫지 않으면 이어서 다시 시도할 수 있습니다.
- 처리 화면의 "처리 시간 측정"에 요청마다 걸린 시간과 입력·추론·출력 토큰 수를 표시합니다(브라우저 콘솔에도 기록). 받아쓰기 응답의 앞부분도 콘솔에 남깁니다.

## 회의록 양식

- 녹음 올리기 화면의 "회의록 양식"에서 기본 양식(주제·논의·결론·Task) 대신 내 양식을 고를 수 있습니다. 양식은 붙여넣거나 md·txt·docx·hwp·hwpx 파일에서 불러옵니다. 양식은 각자 브라우저에 저장됩니다.
- 내 양식을 고르면 회의록 정리 요청에 양식을 함께 보내, 제목·항목 순서와 표·목록·체크박스 모양을 지킨 마크다운으로 받습니다. 괄호 안 설명과 자리 표시는 작성 지침으로 씁니다. 결과는 양식 모양 그대로 그려져 그 자리에서 고칠 수 있습니다.
- 이미 작성한 회의록을 양식으로 올려도 됩니다. 그 안의 내용은 형식 참고로만 쓰고, 이번 회의 내용으로 새로 씁니다.
- 팀이 같은 양식을 쓰려면 양식 파일을 각자 올립니다(공유 링크 기능은 없음).
- 결과 화면 위쪽에서 양식·정리 수준·정리 스타일을 바꿔 [이대로 다시 정리]를 누르면, 받아쓴 대화록으로 회의록만 다시 만듭니다(녹음을 다시 올리지 않음, 요청 1번).
- 회의록 문장은 "~함", "~음", 명사로 끝맺는 개조식으로 쓰게 합니다.
- 정리 스타일: **발언자별**(안건 → 발언자별 의견), **안건별 요약**(발언자 구분 없이 요점, 사람은 결정·담당 관련일 때만 괄호), **흐름순**(논의 순서대로 제기 → 반응 → 결론), **직접 작성**(사용자가 쓴 정리 방식을 가장 우선해서 따름, 브라우저에 저장). 녹음 올리기 화면과 결과 화면의 다시 정리에서 고릅니다. 내 양식이 발표자별 구성이어도 다른 스타일을 고르면 양식의 큰 구성만 따르고 논의 내용은 그 스타일로 씁니다.

## 양식 파일로 받기 (입력 형식 = 출력 형식)

올린 양식 파일과 같은 형식으로, **원본 파일을 그대로 두고 칸 안의 글자만 바꿔** 돌려줍니다. 변환 단계가 없어 로고·머리 표·글꼴이 원본 그대로 남습니다.

| 올린 양식 | 화면 회의록 | 내려받기 |
|---|---|---|
| .hwpx | 양식 항목대로 | 회사 양식에 채우기 (.hwpx) — 원본에 글자만 채움 |
| .docx | 양식 항목대로 | 회사 양식에 채우기 (.docx) — 원본에 글자만 채움 |
| .hwp | 양식 항목대로 | 기본 서식 파일만. 서식 그대로 받으려면 한글에서 [다른 이름으로 저장 → HWPX]로 저장해 올림 |
| md·txt·붙여넣기·기본 양식 | 양식 항목대로 | 기본 서식 파일 (아래) |

- 결과 화면의 [형식 ▾ 파일로 받기]에서 서식 파일이 있는 양식은 "회사 양식에 채우기"가 기본으로 선택되고, 같은 형식의 기본 서식 항목은 헷갈리지 않게 빠집니다. 결과 화면 위 양식 이름 옆에 서식 파일 포함 여부가 표시됩니다.
- 어떤 양식이든 결과 화면의 [형식 ▾ 파일로 받기]에서 **기본 서식**의 워드(.docx, 직접 만든 OOXML: 제목·목록 들여쓰기·굵게·표, 맑은 고딕), 한글(.hwpx, hwp-convert `markdownToHwpx` — 한글로 열어 확인함), 마크다운(.md)으로도 받을 수 있습니다. 기본 서식 파일은 Gemini 요청을 쓰지 않습니다.
- .hwp를 브라우저에서 쓰려면 hwpx로 바꿔야 하는데, 이 변환(hwp-convert)에서 로고 그림과 머리 표가 깨지는 것을 한글로 PDF를 뽑아 확인했습니다. 그래서 hwp는 글자 구성만 읽고 서식 파일은 보관하지 않습니다. 예전에 hwp로 등록한 양식은 열 때 서식 파일을 빼고 글자 구성만 남깁니다.
- 받을 때는 양식의 표 칸(C번호)과 문단(P번호, 글자 모양 조각 포함) 목록과 화면의 최종 회의록을 Gemini(Flash-Lite)에게 보내 "어느 칸에 어떤 문단을, 어느 예시 문단의 모양으로" 넣을지 계획을 받습니다(요청 1번). 계획대로 예시 문단을 복제해 글자만 바꿉니다.
- 왼쪽 머리글이 작성자·부서·비고·결재 등인 칸은 코드에서 바꾸지 않습니다. 한 문단에 이어 쓴 목록 항목은 항목마다 문단으로 나누고, 마크다운 기호(**, [ ])는 뺍니다.
- hwpx: mimetype을 맨 앞에 압축 없이 두고, 바꾼 문단의 줄 배치 정보(linesegarray)는 지워 한글이 다시 계산하게 합니다. 문단 id는 문서 전체에서 겹치지 않게 매깁니다.
- docx: 바꾼 문단의 고유번호(paraId 등)와 책갈피 같은 부속 요소는 뺍니다. 한글이 내보낸 docx는 내용 칸 행에 한 쪽 가득한 최소 높이가 걸려 있어 워드에서 다음 쪽으로 넘치므로, 내용을 채운 행은 큰 최소 높이와 행 나눔 금지를 풉니다.

## 알려진 한계

- 화자 구분 정확도는 받아쓰기 모델 성능에 달려 있습니다(3명 이상은 모델 문서상 실험 단계, 사람 수를 미리 알려주는 설정 없음). 같은 사람이 두 번호로 나뉘면 화자 이름 단계에서 같은 이름을 넣어 합칩니다.
- 30분이 넘는 녹음은 조각마다 화자 번호를 다시 맞추므로 더 흔들릴 수 있습니다.
- 브라우저에서 .hwp 파일을 쓰는 방법이 없어 한글 결과물은 .hwpx입니다. .hwp가 필요하면 한글에서 다른 이름으로 저장합니다.
- 무료 키로 보낸 녹음·결과는 Google이 서비스 개선에 쓸 수 있습니다. 민감한 회의에는 쓰지 않습니다.
